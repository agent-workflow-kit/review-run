# review-run: plan

Implements [interface.md](interface.md) and [design.md](design.md). Issues are expanded into bite-sized TDD steps when picked up; this plan fixes the stages, the module map, the conventions and the version roadmap.

## Conventions for every stage

- **Gateway boundary.** Every subprocess (forgectl, pr-comment, agent-spawn, claude-session, wtctl, `bwrap`, `socat`, the `/proc` scan) goes through `src/review_run/gateway.py`; tests substitute fakes. No other module spawns a process.
- **Fakes and pinned schemas.** Fake binaries for forgectl, pr-comment, agent-spawn, claude-session and wtctl live in `tests/fakebin/` (copied per repo, never shared). Sibling schemas the tool reads (forgectl `show`, `files`, `diff`, `ci`; pr-comment's review-draft schema and `draft new`/`draft check` output; agent-spawn's launch result and error envelope; claude-session's `status` outcome object) are copied into `tests/` pinned to a version and every fake's output is validated against them.
- **Process and live split.** Unit and process tests run in `make verify` (process tests that need real bubblewrap skip when it is unusable). Tests that need a real model or real host carry the pytest marker `live`, are deselected by default and never run in CI.
- **Golden files** for every `--json` output, validated against `schemas/`.
- **Spike regressions.** Every behavior relied on from the live verification is a test. Spike A's findings: missing-skill detection, `--no-implicit-done`, large-input behavior, and the normalization fixture (a finding property the model invented, such as an extra free-text field, and `"suggestion": null`). Spike C's deny profile: the `Agent` and `Task` tools and every other unused tool are absent from the init tool list, and the list equals the pinned allowed set. Spike B's attack set, each a process test under real bubblewrap with the expected result in the table:

| Attack | Expected result |
|---|---|
| read planted canary files under a fake home | not found or empty; the canary never appears in the output |
| connect to a planted Unix socket and to an abstract socket | connection refused or absent |
| read another process's `/proc/<pid>/environ` | the process is not visible (pid namespace) |
| write outside the throwaway | read-only file system error; nothing outside changes |
| a `setsid` daemon that outlives the command | gone when the command ends (pid namespace); `wtctl remove` succeeds |
| symlink swap of the output file | review-run reads only through the descriptor it opened before the child; the swapped target is never read |
| an output flood | stopped at the output cap; the run records `truncated` |
| a command that ignores SIGTERM | SIGKILL 5 s after SIGTERM; the run records `timed_out` |
| a nested user namespace (`unshare -Urm`) | fails |
| a 2 GB write into the workspace | stopped by the workspace bound; the run records `failed` |

- **`make verify`** passes before every commit. Untrusted text never appears in argv, env, hook payloads, audit records or error messages; a test greps every output for planted markers. Files and directories created by review-run have modes 0600 and 0700.

## Module map

| Module | Stage | Responsibility |
|---|---|---|
| `cli` | 0 | argparse subcommands, global flags, exit-code mapping |
| `config` | 0 | YAML, drop-ins, env, per-repo overrides, validation |
| `gateway` | 0 | the only place that spawns processes |
| `store` | 0 | SQLite (WAL, additive migrations), run directory, leases, ids |
| `sanitize` | 0 | the sanitizer (used by `prompt`, `coderun` and human output) |
| `audit` | 0 | `audit.jsonl`, `log.jsonl`, `export` |
| `prefetch` | 1 | forgectl and `pr-comment draft new` reads, head comparison, manifest, per-file patches, size caps |
| `prompt` | 1 | fenced prompt and input files, nonce |
| `launch` | 2 | agent-spawn arguments, result handling, and the per-phase signal handling (`signals`) |
| `finalize` | 2 | artifact checks, normalization, meta derivation, teardown |
| `hooks` | 2 | hook execution and payloads |
| `plugin/` | 2 | bundled `review-pr` skill and permission profile |
| `runs` | 3 | `resume`, `wait`, the refresh of `show`, `cancel`, `reconcile` (finalization by another process, expiry, the label recovery, outbox redelivery), `prune`, `cron` |
| `coderun` | 4 | throwaway, sandboxed runner, output descriptor, removal (output through `sanitize`) |

## Stage 0: Scaffold, config, store, gateway, sanitizer

**Goal**: A CLI skeleton that loads and validates config, keeps runs in `state.db`, writes audit and log records and spawns nothing except through the gateway.
**Success Criteria**: `review-run --version`, `list --json` and `show` on an empty store work; config errors name the key; migrations apply; the gateway is the single subprocess seam with a recording fake (every call has a timeout); the sanitizer marks and neutralizes untrusted text for every printer.
**Tests**: config precedence and validation (flags, repo override, env, global, defaults); schema validation of `config.example.yaml`; store CAS and lease behavior under concurrent processes; id prefix resolution (unique, ambiguous exit 21, too short exit 2); golden `list` and `show` outputs; a grep test that no module imports `subprocess` outside `gateway`; a golden per row of the reasons table (reason, state, exit code, `--json` shape); config tests for `ro_binds`, `env_allow` and `guidelines_file` refusals, `escalation_ttl`, `plugin_dirs`, `max_turns` and the grammar rules; audit goldens (one record pair per action, the `attempt_id`, the veto record); file modes (0700 and 0600, umask 077) and a symlinked state root refused (`state_unsafe`); the `finalize` audit record and a run pair whose runner died (closed by none, the `finalize` record ends the run); 61 caller labels exit 2 `too_many_labels` and `max_files: 2001` is a config error; an id reserved by a vetoed attempt is never allocated again (forced collision in the id generator); a golden for each output-shape rule (`show` of a canceled run exits 0 with the run object, `wait` on it exits 143 with the run object, an interrupted `wait` exits 143 with empty stdout); a fake sibling that never exits is ended at its timeout (`lower_code: timeout`); `ro_binds` through a symlink to a credential directory, `~/.cargo`, `/mnt/c` and `/mnt` each refused, and the bound path is the realpath; `DATABASE_URL`, `PGPASSFILE` and `HTTPS_PROXY` refused in `env_allow` and `env_allowlist`; duplicate plugin names, a plugin named `review-run` and a group-writable plugin directory are config errors; a 0755 state root is tightened to 0700 and `list` with a symlinked state root exits 12 `state_unsafe`; `export` goldens; `list` filters, limit and `truncated` goldens; sanitizer fixtures (TAG characters, bidi controls, U+2028, variation selectors, case-variant `<untrusted` openers and closers, NUL, invalid UTF-8, ANSI, CR tricks).
**Status**: Not Started

## Stage 1: Pre-fetch and prompt

**Goal**: From a PR reference, produce the anchor, manifest, per-file patches and fenced prompt, with head consistency and size policy, and print them with `run --dry-run` (the manifest part of the dry run; its launch part lands in Stage 2 and its code-run plan in Stage 4).
**Success Criteria**: Anchor from `pr-comment draft new`; mismatching heads retry once then `stale_head`; `too_large` and `files_complete: false` fail; files over the per-file limit split at hunk boundaries; caps yield skipped entries; closed PR and unknown host refused (exit 20); a null `anchor.merge_base_sha` is accepted.
**Tests**: fakes for each forgectl read incl. head flips; manifest and coverage preview goldens; fence neutralization (`</untrusted` in a title, a path, a diff line); nonce uniqueness; prompt contains no raw diff; a property test that provided, skipped, binary and empty entries together equal the manifest and the changed files; renames, quoted and TAB paths, a diff-header count mismatch (`diff_files_mismatch`), binary and empty classification and the stop rule; the caps goldens (PR body, labels, CI summary, skipped rows); `forgectl show` with `state: merged` (exit 20 `not_open`), exit 2 `invalid_pr` (exit 2) and exit 12 (`lower_failed`); `run --dry-run` of an unknown PR prints the envelope and exits 10; `draft new` with `merge_base_sha: null` and a complete diff (the run continues); a patch line with U+202E and one with `</ untrusted` (marked and neutralized, line numbers unchanged); a patch whose sanitized size crosses `max_file_bytes` is split; variation selectors and U+3164 marked; a binary entry after the stop keeps `binary`, a first file larger than `max_total_bytes` (`too_large`), a file whose parts would pass `max_files` (`skipped(file_cap)`) and 10000 files (`too_large`); budget goldens per field (a 2 KiB title, a 300-byte label); the nonce is 32 hex characters and differs per run and per resume.
**Status**: Not Started

## Stage 2: Launch, finalize, hooks, bundled skill

**Goal**: A blocking `run` that launches the session through agent-spawn, finalizes the artifact and exits with the interface's codes.
**Success Criteria**: Exact launch arguments (table in the interface), the checks of run order steps 1 and 2 (`tool_too_old`, `no_tmux`, `label_reserved`, `too_many_labels`, `pr_too_long`, `previous_mismatch`, `skill_not_found`) before anything is allocated; the outcome mapping of every agent-spawn result row to states and exits; implicit done, missing artifact, mismatch, missing skill, invalid artifact each fail with the right reason and exit 22; normalization closed list; `draft check` gate; `meta.review_run` derived; end head recorded; teardown (never `--force`, never `--ephemeral`); `pre-run`, `post-run` and `post-escalate` hooks; the init tool list compared with the pinned set (`tools_unexpected` and `tools_unchecked` are warnings, never failures); the bundled skill and profile ship.
**Tests**: golden `run` outputs per outcome (a fake agent-spawn result per row of the launch mapping table); version-check goldens with a fake agent-spawn reporting an old version, and a dry-run golden per mapped exit (exit 20 `lower_refused`, exit 2 with `tool: termctl` `no_tmux`, exit 12 `tool_missing`, exit 13 and unparsable output `lower_failed`); normalization fixtures from the spike A failures (`failure_scenario`, `"suggestion": null`) plus an invented property inside `suggestion`, `event: approve` and a padded title (passes `draft check`); derived-meta recomputation ignoring a lying model; a golden that an artifact with a wrong `anchor` is stored with the right one; each session-claim rule violated (an 8 MiB summary, 11 reasons, a reason with a newline, an unknown verdict) ends `artifact_invalid` with the right kind and no text in the output; strict parsing (duplicate keys, deep nesting, a lone surrogate, a file that grows after its size was reported); frozen-artifact copy with a size/hash mismatch; skill check per mode (headless reads the init skills of the awaited run, interactive gives `skill_unchecked`); skill resolution and the placeholder check; `run --override-escalation` without a TTY exits 2, the override makes exit 13 pass and a veto still vetoes; the dry run's launch part; init-object fixtures (init on line 3 after hook lines, a skill name printed by the model after init is not accepted, a 2 MiB file without init gives `skill_missing`, a symlinked `result_path` gives `skill_missing`); an init `tools` list with an extra tool gives the warning `tools_unexpected` with its count and the run still ends `done`, and a configured profile gives `tools_unchecked`; `meta.review_run.session` per profile kind and sandbox level, and audit `inputs` carry the profile hash; `draft check` exit 12 gives `internal` with `failure.tool: pr-comment`, exit 2 with a schema error gives kind `schema`; a BOM-prefixed artifact, a UTF-16 artifact, `1e999` and a 5000-digit integer are each `artifact_invalid`; claims goldens (U+E0041 (TAG) and U+202E rejected, U+E000 (private use) and an unassigned code point accepted, U+FE0F rejected); a rendered-header golden, and a PR body carrying a forged instruction and a forged closing fence appears only inside its fence, neutralized; a dry-run golden per mapped exit; `post-escalate` once per escalation; `live`: the round trip with haiku, the missing skill, the init tool list equals the pinned set (denying an absent name is accepted). Depends on claude-session's `--no-implicit-done` and agent-spawn's pass-through (cross-tool issues); until they ship, tests use fakes (the step 1 version check exits 12 `tool_too_old` on an older sibling) and the `live` recovery test is skipped.
**Status**: Not Started

## Stage 3: Escalation, resume, cancel, signals, reconcile

**Goal**: Runs survive escalation, a dead runner, cancellation and a second finalizer.
**Success Criteria**: `escalated` keeps the agent; `resume` verifies the stored agent id and finalizes like `run`; `show`/`wait`/`reconcile` finalize runs resumed elsewhere exactly once; a cancellation is recorded on the row first and excludes the move into finalize, so exactly one process ends the run; signals are handled per phase ([Signals](interface.md#signals)) and end the run `canceled` with exit 130/143; `cancel` ends a running or escalated run and `escalation_ttl` expires an escalated one; a dead runner never orphans a live session (the id is stored at launch, the result file and the one label lookup cover the rest); finalize is re-runnable at any step; `--no-wait`; `wait`; `reconcile` repairs lost runs, expired escalations and pending teardowns.
**Tests**: concurrent finalizers (process test, one winner) and a race of `resume` and `reconcile`; kill the runner at each phase and reconcile (`wait` on a run killed in `prefetch` returns exit 12 `runner_lost`); SIGKILL of the runner during the session and while `launch` is in flight (reconcile adopts the id from `launch.json`); SIGKILL of the runner and the launcher between allocation and the result file (the label recovery adopts exactly one matching agent, otherwise `runner_lost` with `agent_unknown`); crash at each finalize step and rerun, with a duplicate hook delivery carrying the same `event_id`; a `show` of an escalated, not-resumed run does nothing; the `cancel` and `resume` race in both orders (a process test that kills each at every step: the run never ends terminal with a live agent, a `resume` that loses to `cancel` exits 20, a `cancel` that loses takes the `stop` path); a null launcher PID inside the 120 s window is not treated as gone; the `post-run` and `post-escalate` payloads carry the session posture and warning codes; audit records survive 5 failed hook deliveries and `prune` skips a run with undelivered events; `reconcile` finalizes and fires the stored per-invocation hook; external `agent-spawn teardown` of an escalated run's agent, then `show` (`agent_gone`); resume of a non-escalated run (exit 20); torn-down agent (`agent_gone`, run object, exit 12); resume failure keeps `escalated`; an answer over the cap; a fenced answer in the built prompt; `cancel` of running, escalated and terminal runs; TTL expiry; signal tests per row of the signals table with a fake agent-spawn that records its signals and `stop` calls (a reported-done session canceled ends `canceled`; SIGHUP leaves the session and a later `wait` finalizes it); `cancel` while the blocking runner's `agent-spawn wait` returns 15 (stopped) and while it returns 0 (already reported): both end `canceled` 143; `cancel` racing the move into `finalize` (one winner, the loser reports the stored row); a runner SIGKILLed after recording the cancellation is ended `canceled` by `show`; `cancel` of an escalated run whose agent finished a newer run externally (finalized, `changed: false`), of an escalated run a human is answering interactively (stop, then `canceled`), with a dead runner and a live launcher (`signal_launcher`), `stop` exits 10, 12 and 20, and a refused teardown (`teardown_refused`, the run stays `canceled`, `reconcile` retries); SIGTERM during `launch` when the launcher has already exited 0 with a live agent (stop, then teardown, `canceled`), and a launcher that does not exit within 60 s (the run stays `running` with the cancellation recorded; `reconcile` adopts from `launch.json` and ends it `canceled`); expiry skips an escalated run whose agent is live, expiry of a run whose agent finished externally finalizes it, and a refused teardown after expiry (`teardown_refused`, retried); config changed between `run` and `resume` (limits, profile file edited, `REVIEW_RUN_SANDBOX=off` in the resumer's environment): the resume uses the stored values, and a finalize by `reconcile` with a different config uses the stored limits; a `resume --hook post-run=X` after a `run --hook post-run=Y`: both fire once and the payload's actor is the resume's; crash after the terminal transaction and before delivery: the next `reconcile` appends the audit records and runs the hook once more with the same `event_id`, an event that fails 5 times is abandoned with `hook_failed`, and a `show` that finalizes waits for a synchronous hook; `resume` of a run whose agent finished externally (finalized, exit 20 `not_escalated`), field values after a resume (`awaited_run`, cleared `reason`, kept `escalated_run`), and a resume of an interactive run passes no `--mode`; one golden per agent-spawn Resume failures row (refusal `tainted` as `lower_refused`, a claude-session `pre-launch` veto as exit 11 with `hook: null`, a launch-phase end keeping `escalated` with the new `escalated_run`, wtctl `busy` as `lower_failed` with `retryable`); a `show` while `launch` is in flight (no `launch.json`, live launcher) changes nothing, and a candidate created before `launch_started_at` is not adopted; a look-alike agent with review-run's labels but another `run=` or kind is never adopted or torn down; `launch.json` holding an envelope with an `agent_id` (`launch_failed`, the agent torn down); a truncated `launch.json` counts as absent; `agent-spawn wait` exiting 12 three times: the run stays `running`, `run` exits 12 `lower_failed`, a later `wait` finalizes it; lease renewal: a finalizer that stops renewing loses the lease after 5 minutes and another finalizer takes over; `live`: needs-input then resume with a new artifact (spike A9).
**Status**: Not Started

## Stage 4: Code run

**Goal**: The optional `run_pr_code` step in a bubblewrap sandbox with safe output capture.
**Success Criteria**: The interface's Code run steps exactly: throwaway, sandbox check, argv-only command, from-scratch environment, no network, pid namespace, limits, output file opened before the child and read through its descriptor, sanitizer, removal after the process tree is gone; skip reasons recorded; nested user namespaces disabled and tmpfs and workspace sizes bounded; a skip reason recorded for every case (`wtctl_missing`, `throwaway_refused`, `ref_unavailable`, `throwaway_failed`, `sandbox_unavailable`, `sandbox_unsupported`, `sandbox_failed`, `throwaway_leaks`); macOS skips.
**Tests**: process tests (need bubblewrap) holding the spike B attack table in Conventions (an `ro_binds` directory replaced by a symlink to a credential directory after validation still binds the original through `--ro-bind-fd`; a symlinked `~/.ssh` target is refused by the contains-or-inside test; a plugin file changed between run creation and launch or resume is `plugin_changed`; `unshare -Urm` fails, a 2 GB write is stopped, a 300 MB tmpfs write fails, a large legitimate file under 256 MiB passes); sanitizer fixtures (NUL, invalid UTF-8, ANSI, bidi, CR tricks, `</untrusted`, and the look-alikes: NBSP, ideographic space, braille blank, a combining mark, fullwidth `<`, long s, a forged closer without the nonce); output flood and `RLIMIT_FSIZE` bound; timeout with a SIGTERM-ignoring setsid grandchild; removal after `in_use`; skip when `bwrap` is faked unusable; the command never sees any variable from review-run's environment (a planted canary), and a canary value in the output is redacted before it enters the prompt; a test per skip reason and the leak cap; without bwrap an unrelated process holding the throwaway is never signaled and blocks removal; the `code_run` audit record; the dry run's code-run plan with the sandbox probe; on WSL, `/usr/lib/wsl/drivers` is absent inside the sandbox; a canary under a refused `ro_binds` path never appears in the output; a million empty files stop the command; SIGKILL of the runner during the code run: `reconcile` removes the throwaway.
**Status**: Not Started

## Stage 5: Retention, cron, export, interactive mode, previous run

**Goal**: The remaining commands and options.
**Success Criteria**: `prune` (never touches non-terminal runs), `cron install|uninstall` (tagged block), `export`, `--mode interactive` pass-through (needs tmux), `--previous` input, and the readiness facts printed by `run --dry-run` (sibling tool versions, the bwrap probe result, the resolved skill and plugin directories, `tool_too_old` conditions).
**Tests**: prune age and state filters; crontab golden with a fake `crontab`; `--previous` fenced input, each refusal (`previous_not_done`, `previous_mismatch`, unknown run), the 64 KiB cap and the stored-hash re-check, and `--previous` of another PR given as a URL (`previous_mismatch` after `show`); `list --head <anchor head>` finds a run whose resolve head differs; `prune` skips a run with `teardown: pending` and `reconcile` reports `teardown_stuck`; cron golden entries with `--json`; the `reconcile` and `prune` output goldens; interactive launch arguments golden including `skill_unchecked`.
**Status**: Not Started

## Stage 6: Live suite, skill evaluation, macOS checklist

**Goal**: Re-verify every relied-on third-party behavior against the current Claude Code and document what only a human can check.
**Success Criteria**: A `live` suite (haiku; deselected) covering the round trip, missing skill, denied tools, the implicit-done recovery, large-PR coverage, a second plugin's skill loaded through `plugin_dirs`, a fork PR's head, the pinned tool inventory (deferred tools appear in the init `tools` list) and the code run under real bubblewrap; the paging measurement (whether a 200 KB input is read whole, deciding `max_file_bytes`); a small eval of the default skill's output discipline (no suggestion fences, one-line titles, exact paths, lines inside hunks) over a fixed set of synthetic PRs; a macOS checklist (everything except the code run, which stays skipped).
**Tests**: the suite itself, run by hand before each minor release.
**Status**: Not Started

## Version roadmap

- **0.x:** stages 0 to 6, released as the stages land (`feat` commits; no `!`).
- **1.0 qualifies when:** the live suite passes against the current Claude Code; claude-session's `--no-implicit-done` and agent-spawn's pass-through have shipped and review-run's recovery test passes live; review-watch drives review-run on the author's machine end to end (headless, an escalated run resumed, a partial-coverage run); the macOS checklist is done for the non-code-run parts; the sandboxed code run has run against real repositories on Linux or WSL; a runner killed during a session is recovered by `reconcile`; the pinned tool inventory matches and a headless run with the bundled profile reports no `tools_unexpected`.
- **1.x (additive):** a seccomp filter for the code-run sandbox; an `install_command` phase with a filtered network proxy; a macOS (Seatbelt) code-run sandbox; a TUI; label add and remove commands; feeding existing PR comments to the reviewer; additional bundled skills; optional multi-agent reviewing as a bundled alternative skill.
- **2.0:** only for a breaking change to the review-draft contract, the `meta.review_run` shape, the exit codes or the run states.
